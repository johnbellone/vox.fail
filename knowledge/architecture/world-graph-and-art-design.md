# Design (proposed): World Graph and Generated Art

Source: `docs/design/world-graph-and-art.md`, 2026-11-25. **Nothing built.**

## Idea
Levels are a **graph of nodes** (village, house, road, well) refined in passes: `intent` -> `layout` -> `massing` -> `structure` -> `dressing`. A **language model never places blocks**; it edits the graph through a small set of tools. Each node carries a **recipe**: a typed, ordered list of building operations (box, roof, cut, openings, trim, ...) that a Rust interpreter expands into voxels, reproducibly from a **seed**. The same Rust code runs native and in wasm, so server, desktop and browser expand identical voxels. Each node also has a **vector** that places it in a **library** of accepted builds (examples, style consistency).

## Why recipes
Today's art is generated by Python scripts (see `architecture/asset-pipeline`). Alternatives were rejected: model-written Python (not wasm, needs a sandbox), model-written Rust/wasm (compiler and runtime in the loop), image/3D services (off-style, not editable). A recipe is **data**, validated by type, deterministic, no code execution; the interpreter is the style. Scales: `character` 5 cm, `prop` 10 cm, `world` 0.5 m.

## Planned crates
`vox-art`, `vox-graph`, `vox-library`, `bins/vox-forge` (CLI plus MCP tools), `apps/forge` (review UI). "No Python."

## Phases
1 `vox-art` with five operations and golden tests; 2 reproduce one existing set; 3 describe the yard as a graph; 4 `vox-forge` with a model refining the yard's house with human review; 5 library and embeddings; 6 per-region graphs tied to world scaling.

## Open questions
Which model provider; operation granularity; who may run the authoring tool on a public world; whether player builds join the library (consent and moderation).

Constraint: all generated art must follow `convention/hard-constraints`.
